## 一、正则的两种创建方式

```js
// 1. 字面量（编译期确定，推荐静态规则）
const re = /header-ceil_([^\s]+)/

// 2. 构造函数（规则需运行时拼接时使用）
const prefix = 'header-ceil_'
const re2 = new RegExp(prefix + '([^\\s]+)')   // 字符串里 \ 要写成 \\

// 3. 动态拼接时的特殊字符转义（. + ? 等有特殊含义，必须转义）
const escape = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
const re3 = new RegExp(escape(userInput))
```

## 二、exec() 返回结构（重点）

`regexp.exec(str)`：匹配成功返回**数组**，失败返回 **`null`**。

```js
const className = 'header-table-ceil header-ceil_name'
const m = /header-ceil_([^\s]+)/.exec(className)
```

| 取值 | 结果 | 说明 |
| --- | --- | --- |
| `m[0]` | `"header-ceil_name"` | **整个正则匹配到的字符串**（含前缀） |
| `m[1]` | `"name"` | **第 1 个捕获组**——第一个 `(...)` 里捕获的内容 |
| `m[2]`、`m[3]`… | 无 | 有几个括号就有几个捕获组，按左括号顺序编号 |
| `m.index` | `18` | 匹配起始位置（附加属性） |
| `m.input` | 原字符串 | 被检索的字符串（附加属性） |
| 匹配失败 | `null` | 所以取值前先判空：`m ? m[1] : null` |

**记忆法**：`[0]` 是"连同前缀的整体"，`[1]` 开始才是"括号里抠出来的部分"。

> 配合 `g` 标志循环提取所有匹配的写法（含括号优先级陷阱），见第五章「循环提取所有匹配」与「番外」章。

## 三、捕获组

### 1. 普通捕获组 `(...)`

按**左括号出现的顺序**从 1 开始编号：

```js
/(\d{4})-(\d{2})-(\d{2})/.exec('2026-09-15')
// m[1]='2026'  m[2]='09'  m[3]='15'
```

### 2. 非捕获组 `(?:...)`

只分组、不捕获、**不占编号**——需要括号影响优先级但不需要提取内容时用：

```js
/(?:ab)+(\d)/.exec('ababab3')
// m[1]='3'，若写成 /(ab)+(\d)/ 则 m[1]='ab'（最后一轮）、m[2]='3'
```

### 3. 命名捕获组 `(?<name>...)`（ES2018）

```js
const m = /(?<year>\d{4})-(?<month>\d{2})/.exec('2026-09-15')
m.groups.year    // '2026' —— 可读性好，不怕括号顺序变化
m[1]             // '2026'（仍然保留编号）
```

### 4. 捕获组的两个衍生用法

```js
// 反向引用：匹配重复单词
/\b(\w+)\s+\1\b/.exec('hello hello world')   // m[1]='hello'

// replace 中的 $1 $2：引用捕获组做替换
'name_xx'.replace(/name_(.+)/, '$1_yy')      // 'xx_yy'
'2026-09-15'.replace(/(\d{4})-(\d{2})-(\d{2})/, '$3/$2/$1')  // '15/09/2026'
```

## 四、字符类与排除型写法 `[^...]`

### 1. 预定义字符类

| 符号 | 含义 | 反义 |
| --- | --- | --- |
| `\d` | 数字 `[0-9]` | `\D` |
| `\w` | 单词字符 `[A-Za-z0-9_]` | `\W` |
| `\s` | 空白（空格/Tab/换行等） | `\S` |
| `.` | 除换行外的任意字符（加 `s` 标志后含换行） | — |

### 2. 字符类 `[...]` 与排除型 `[^...]`

```js
/[abc]/      // a 或 b 或 c
/[^abc]/     // 除 a、b、c 外的任意一个字符
/[^\s]+/     // 一个及以上"非空白字符"——以空白为天然边界
```

**引子实例拆解**：`/header-ceil_([^\s]+)/` 匹配 `"header-table-ceil header-ceil_name"`

```js
header-ceil_   ← 字面量前缀，精确定位
([^\s]+)       ← 从前缀后开始，连续吃"非空白"，遇到空格即停
```

所以 `m[1]` 捕获到 `name`；即使列标识含下划线（`header-ceil_quality_monitor`），也会完整捕获 `quality_monitor`——**边界是空格不是下划线**。

### 3. 贪婪 vs 懒惰

量词默认**贪婪**（尽量多吃），加 `?` 变**懒惰**（尽量少吃）：

```js
/'.*'/.exec('"a" and "b"')      // m[0] = '"a" and "b"'  ← 吃过头
/'.*?'/.exec('"a" and "b"')     // m[0] = '"a"'          ← 到第一个引号就停
```

常用量词：`+`（≥1 次）、`*`（≥0 次）、`?`（0 或 1 次）、`{n,m}`（n 到 m 次）。

## 五、六个常用方法速查

```js
const re = /\d+/

// 1. test：是否存在匹配（布尔）—— 校验场景首选
/\d+/.test('abc123')                       // true

// 2. exec：详情数组（含捕获组），失败 null —— 提取场景
/\w+_(\w+)/.exec('user_name')              // ['user_name', 'name', ...]

// 3. match：挂在字符串上
'abc123def456'.match(/\d+/)                // 无 g：['123', index, input]（同 exec）
'abc123def456'.match(/\d+/g)               // 有 g：['123', '456']（纯数组，无捕获组信息！）

// 4. search：返回首个匹配位置，无匹配 -1
'abc123'.search(/\d/)                      // 3

// 5. replace：替换（可用 $1 引用捕获组；g 标志替换全部）
'a1b2'.replace(/\d/g, '#')                 // 'a#b#'
'hello world'.replace(/(\w+)\s(\w+)/, '$2 $1')  // 'world hello'

// 6. split：按匹配切分
'a, b;c'.split(/[,;]\s*/)                  // ['a', 'b', 'c']
```

**exec 与 match 的关系**：非 g 时 `str.match(re)` ≡ `re.exec(str)`；有 g 时 match 退化为"所有整体匹配的纯数组"，**丢失捕获组**——需要捕获组详情时用 exec 循环。

### 循环提取所有匹配（g 标志 + exec）

`exec()` 每次只返回**一个**匹配；带 `g` 标志时从 `lastIndex` 继续。提取所有匹配的标准模板：

```js
const materialIdRegex = /src=["'](\d+)["']/g   // 必须带 g 标志
let idMatch
while ((idMatch = materialIdRegex.exec(contentHtml)) !== null) {
  materialIdSet.add(Number(idMatch[1]))
}
```

- 循环终止条件：`exec()` 返回 `null`（找完全文，此时 lastIndex 自动归 0）
- 循环体内 `idMatch[0]` = 整体匹配（如 `src="123"`），`idMatch[1]` = 第一个分组（如 `123`）
- `while` 条件里 `(idMatch = ...)` 的括号为什么不能省 → 见下方「番外」章

等价简洁写法（ES2020，babel 环境可用）：

```js
for (const m of contentHtml.matchAll(materialIdRegex)) {
  materialIdSet.add(Number(m[1]))
}
```

`matchAll` 返回迭代器、**无副作用**（不改变正则的 `lastIndex`），不需要手动管游标；要求正则必须带 `g`，否则抛 TypeError。

## 番外：`while ((m = re.exec(s)) !== null)` 语法拆解

### 1. 赋值表达式自身的值

`=` 是运算符，**整个赋值表达式的值 = 被赋的那个值**：

```js
let x
console.log((x = 5))   // 5
```

所以 `(idMatch = regex.exec(str))` 的求值顺序：

1. 执行 `exec()` 得到结果
2. 存入 `idMatch`
3. 括号表达式的值 = 刚赋的值（匹配数组或 `null`）

`while` 条件实际判断的就是"有没有匹配到"，循环体内 `idMatch` 直接可用。

### 2. 为什么括号不能省（运算符优先级）

`!==` 优先级**高于** `=`。不加括号：

```js
while (idMatch = regex.exec(str) !== null)   // ❌ 错误用法
// 实际解析为: idMatch = (regex.exec(str) !== null)
```

结果是 `idMatch` 被赋成 **true/false**，循环能跑但 `idMatch[1]` 取不到分组数据。括号强制"先赋值、再比较"。

## 六、标志位（flags）

| 标志  | 含义             | 注意                        |
| --- | -------------- | ------------------------- |
| `g` | 全局匹配           | **exec/match 行为变化**（见下方坑） |
| `i` | 忽略大小写          | `/abc/i` 可匹配 ABC          |
| `m` | 多行模式           | 使 `^` `$` 匹配每行的行首行尾       |
| `s` | dotAll（ES2018） | 使 `.` 也匹配换行符              |
| `u` | Unicode        | 正确处理代理对（emoji 等）          |

### ⚠️ g 标志 + exec 的 lastIndex 陷阱

```js
const re = /a/g
re.exec('aaa')   // ['a']，re.lastIndex 变为 1
re.exec('aaa')   // ['a']，lastIndex 变为 2 —— 从上次位置继续！
re.exec('aaa')   // ['a']，lastIndex 变为 3
re.exec('aaa')   // null，lastIndex 归 0
```

同一个带 g 的正则实例反复 `exec`/`test`，会从 `lastIndex` 继续，导致**"时中时不中"**。规避：

```js
// 方案一：不用 g（单次校验/提取场景）
// 方案二：每次用字面量新建实例
// 方案三：循环前手动 re.lastIndex = 0
```

## 七、实战片段集

```js
// 1. 从 class 解析标识（本项目实例：header-ceil_<value>）
const parseValue = (th) => {
  const m = /header-ceil_([^\s]+)/.exec(th.className || '')
  return m ? m[1] : null
}

// 2. 手机号（简化校验）
/^1[3-9]\d{9}$/.test('13800138000')        // true

// 3. 邮箱（简化校验）
/^[\w.%-]+@[\w.-]+\.\w{2,}$/.test('a@b.com')

// 4. 手写 trim
'  ab  '.replace(/^\s+|\s+$/g, '')         // 'ab'

// 5. 下划线转驼峰
'header_cell_value'.replace(/_(\w)/g, (m, p1) => p1.toUpperCase())  // 'headerCellValue'

// 6. 驼峰转下划线
'headerCellValue'.replace(/([A-Z])/g, '_$1').toLowerCase()          // 'header_cell_value'

// 7. 千分位
'1234567.89'.replace(/\B(?=(\d{3})+(?!\d))/g, ',')                  // '1,234,567.89'

// 8. 提取 URL 查询参数
const getParam = (url, key) => {
  const m = new RegExp(`[?&]${key}=([^&]*)`).exec(url)
  return m ? decodeURIComponent(m[1]) : null
}

// 9. 提交时反推引用 ID（文章草稿箱 materialIds 实例）
// 正文 src 替换完成后，src="纯数字" 即素材引用；正则提取 + Set 去重：
const materialIdRegex = /src=["'](\d+)["']/g
const materialIdSet = new Set()
let idMatch
while ((idMatch = materialIdRegex.exec(contentHtml)) !== null) {
  materialIdSet.add(Number(idMatch[1]))
}
return { ...this.formData, content: contentHtml, materialIds: Array.from(materialIdSet) }
// 相比"插入素材时 push"的优势：删除素材、Ctrl+Z 撤销、编辑器内复制粘贴
// 都会被自动正确同步（提交时以最终内容为准）
```

## 八、常见坑清单

| #   | 坑                                  | 说明 / 规避                                                                                  |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| 1   | **g 标志下 exec/test 的 lastIndex 残留** | 同一实例循环调用"时中时不中"；见第六章，避免共用带 g 实例或手动归零                                                     |
| 2   | **特殊字符未转义**                        | `.` `+` `?` `(` `)` `[` `]` `{` `}` `\` `^` `$` `\|` 有特殊含义；动态拼接用 `new RegExp(escape(s))` |
| 3   | **贪婪匹配吃过头**                        | `.*` 会吃到最后一个匹配点；需要最小结果用懒惰 `.*?`                                                          |
| 4   | **previousSibling 式的节点混淆**（对比记忆）   | 正则没有这个问题，但 `match` 有 g / 无 g 返回结构不同，别混用                                                  |
| 5   | **`^` `$` 默认只锚整个字符串首尾**            | 多行文本要逐行锚定需加 `m` 标志                                                                       |
| 6   | **`.` 不匹配换行**                      | 跨行内容加 `s` 标志或用 `[\s\S]`                                                                  |
| 7   | **捕获组编号数错**                        | 括号嵌套时按左括号顺序编号；只分组不提取用 `(?:...)`；复杂场景用命名组 `(?<name>...)`                                  |
| 8   | **match 有 g 时拿不到捕获组**              | 需要捕获组详情用 exec 循环提取，标准模板见第五章「循环提取所有匹配」；`while ((m = re.exec(s)) !== null)` 的语法细节见「番外」章    |
