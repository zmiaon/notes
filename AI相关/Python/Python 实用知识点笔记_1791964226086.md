## 一、asyncio（异步 I/O 框架）

Python 标准库自带的异步框架，核心是 **单线程内用事件循环实现并发** ，专治 I/O 等待密集场景（网络请求、文件、数据库）。

### 核心概念
| 概念 | 作用 | JS 对应物 |
| :--- | :--- | :--- |
| `async def` | 定义协程函数，调用只返回协程对象，不执行 | `async function` |
| `await` | 挂起协程，交还控制权，等待结果 | `await` |
| `EventLoop` | 调度所有协程的核心 | JS 事件循环 |
| `Task` | 把协程包装成可调度任务 | Promise |
| `Future` | 未完成结果的占位 | Promise |

 **关键差异** ：JS 异步是运行时自动启动的；Python 需显式启动事件循环（`asyncio.run()`）。

### 最小示例
```python
import asyncio

async def fetch(name, delay):
    print(f"{name} 开始")
    await asyncio.sleep(delay)   # 模拟 I/O 等待，非阻塞
    print(f"{name} 完成")
    return f"{name}-result"

async def main():
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
        fetch("C", 3),
    )
    print(results)

asyncio.run(main())   # 启动事件循环
```

### 常用 API
| API | 用途 |
| :--- | :--- |
| `asyncio.run(coro)` | 启动事件循环运行主协程（3.7+ 推荐入口） |
| `asyncio.gather(*coros)` | 并发运行多个协程，按顺序返回结果 |
| `asyncio.create_task(coro)` | 包装成 Task 立即调度 |
| `asyncio.wait_for(coro, timeout)` | 设置超时 |
| `asyncio.sleep(sec)` | 异步等待，不阻塞事件循环 |

### 避坑要点
1.  **不要混用同步阻塞调用** ：协程里用 `time.sleep()`、`requests` 会 **阻塞整个事件循环** ，并发失效。
2.  **await 的对象必须是 awaitable** （协程 / Task / Future）。
3.  **适合 I/O 密集** ；CPU 密集用 `multiprocessing`。
4.  **一个线程一个事件循环** ，不要嵌套 `asyncio.run()`。

### 并发方案对比
| 方案 | 适用场景 | 特点 |
| :--- | :--- | :--- |
| `asyncio` | 高并发 I/O | 单线程、开销小、需异步库配合 |
| `threading` | I/O 密集用同步库 | 受 GIL 限制，切换开销大 |
| `multiprocessing` | CPU 密集 | 绕过 GIL，资源开销大 |

## 二、ainvoke 与使用场景

`ainvoke` 是 LangChain 中所有 Runnable 对象（ChatModel、Prompt、Chain、Retriever）的 **异步调用方法** 。

| 方法 | 说明 |
| :--- | :--- |
| `invoke` | 同步调用，阻塞等待 |
| `ainvoke` | 异步调用，返回可 await 的协程 |
| `batch` / `abatch` | 批量同步 / 批量异步 |
| `stream` / `astream` | 流式同步 / 流式异步 |

### 使用场景
1.  **高并发批量调用** ：配合 `asyncio.gather` 或 `abatch`，总耗时约等于最慢一次。
2.  **异步 Web 框架** ：FastAPI / aiohttp 的 `async def` 视图里必须用 `ainvoke`，否则阻塞事件循环。
3.  **流式输出** ：`astream` 的底层机制，`ainvoke` 是非流式版本。
4.  **异步 Agent / Chain 组合** ：各环节用异步形式串联。

```python
results = await asyncio.gather(
    model.ainvoke("问题1"),
    model.ainvoke("问题2"),
    model.ainvoke("问题3"),
)
```

## 三、列表切片

语法 `列表[start:end:step]`，冒号是 **分隔符** ，不是参数。

```python
conversation_messages[-(max_pairs * 2):]
#                   ↑start        ↑end为空  ↑step为空
```

- `-(max_pairs * 2)`：从倒数第 N 个开始
- 冒号后 end 为空：取到末尾
- 整体： **取列表最后 N 个元素** 

### 要点
1.  **包头不包尾** ：`[a:b]` 取 a 到 b-1。
2. 返回 **新列表** ，修改不影响原列表。
3.  **越界不报错** ：N 超过长度时自动取全部。
4. `[-(N):-1]` 与 `[-(N):]` 含义不同，注意区分。

### 业务语义（对话裁剪）
消息成对出现（一问一答），要保留 `max_pairs` 对，就取 `max_pairs * 2` 条，实现 **控制上下文长度、节省 token** 。

## 四、列表推导式

```python
[m for m in messages if m.get("role") != "system"]
 ↑    ↑              ↑
输出  遍历来源        筛选条件
```

 **含义** ：遍历 messages，把 `role != "system"` 的消息原样收集成新列表。

### 等价写法
```python
conversation_msgs = []
for m in messages:
    if m.get("role") != "system":
        conversation_msgs.append(m)
```

### 执行顺序（逐个元素，边遍历边判断边放入）
```
for m in messages:              # ① 取一个元素绑定给 m
    if 条件成立:                 # ② 立即判断
        把最前面表达式的结果放入  # ③ 通过才放入，否则跳过
```

最前面的表达式决定 **结果列表里装什么** ，可加工：
```python
roles = [m.get("role") for m in messages if ...]
contents = [m.get("content") for m in messages if ...]
```

### 整体逻辑示例
```python
# 分离 system 和对话
system_msgs = [m for m in messages if m.get("role") == "system"]
conversation_msgs = [m for m in messages if m.get("role") != "system"]

# 只保留最近的
recent_msgs = conversation_msgs[-(max_pairs * 2):]

# 返回：system + 最近对话
return system_msgs + recent_msgs
```

## 五、dict 的取值与赋值

 **重要纠正** ：dict 有 `get` 方法，但 **没有 `set` 方法** ，赋值用下标。

```python
d = {"name": "小明"}

d.get("name")        # 取值
d["name"]            # 取值
d["age"] = 18        # 赋值（下标）
d["name"] = "小红"    # 覆盖
```

### `d[key]` vs `d.get(key)` 的区别
| 写法 | key 存在 | key 不存在 |
| :--- | :--- | :--- |
| `d["key"]` | 返回对应值 | 抛 `KeyError` |
| `d.get("key")` | 返回对应值 | 返回 `None` 或指定默认值 |

```python
d.get("role")            # 不存在返回 None
d.get("role", "user")    # 不存在返回 "user"
```

### 常用方法
| 操作 | 写法 |
| :--- | :--- |
| 赋值/覆盖 | `d[key] = value` |
| 批量合并 | `d.update({...})` |
| 安全取值 | `d.get(key, default)` |
| 删除 | `d.pop(key)` / `del d[key]` |
| 判断 key | `key in d` |
| 取值且默认初始化 | `d.setdefault(key, default)` |

> 注意：Python 里 `set` 是 **集合类型** ，不是给 dict 赋值的函数，别混淆。

## 六、print 参数详解

```python
print(chunk.content, end="", flush=True)
```

| 参数 | 作用 |
| :--- | :--- |
| `chunk.content` | 位置参数，要输出的内容 |
| `end=""` | 控制结尾追加的字符（默认 `\n`），设为空即 **不换行**  |
| `flush=True` |  **强制立即刷新缓冲区** ，内容马上显示 |

### 流式输出中的作用
- `end=""`：避免每小块占一行，让输出连续拼接
- `flush=True`：避免缓冲延迟，实现「边生成边显示」的打字机效果

```python
# 同步流式
for chunk in model.stream("写一首短诗"):
    print(chunk.content, end="", flush=True)

# 异步流式
async for chunk in model.astream("写一首短诗"):
    print(chunk.content, end="", flush=True)
```

## 七、`*values` 可变位置参数

```python
def print(*values: object, sep=" ", end="\n", file=None, flush=False):
```

`*values` 是 **可变位置参数** （var-positional），不是指针，`values` 是一个 **元组** 。

### 收集规则
- 所有 **位置参数**  → 全部进 `*values`，打包成 tuple
- 带名字的 **关键字参数** （`sep=`、`end=`）→ 被对应形参接走

```python
print("a", "b", "c", sep="-")
# "a"、"b"、"c" → values = ("a", "b", "c")
# sep="-"     → sep = "-"
# 输出：a-b-c
```

### 与 `**kwargs` 的对称规则
| 语法 | 收集什么 | 打包成 |
| :--- | :--- | :--- |
| `*args` | 多余的 **位置参数**  | `tuple`（不可变、有序、性能好） |
| ` **kwargs` | 多余的** 关键字参数** | `dict`（带名字，key-value） |

 **为什么是元组** ：参数是只读输入语义，元组不可变更安全；且位置参数天然有序，与元组语义匹配。

### 解包（调用时的反向语法）
```python
nums = [1, 2, 3]
print(*nums)          # 等价于 print(1, 2, 3)

d = {"sep": "-"}
print("a", "b", **d)  # 等价于 print("a", "b", sep="-")
```

### 注意
- 形参 `args` 是元组，`args[0] = x` 会报 `TypeError`，需先 `list(args)`。
- 位置参数必须在关键字参数前，否则 `SyntaxError`。

## 八、with 上下文管理器

作用是 **保证资源使用完后被自动、可靠地释放** ，无论是否发生异常。

### 对比
```python
# 不用 with：需手动 close，中途报错可能执行不到
f = open("a.txt", "r")
try:
    data = f.read()
finally:
    f.close()

# 用 with：自动关闭
with open("a.txt", "r") as f:
    data = f.read()
```

### 底层机制
| 方法 | 调用时机 | 作用 |
| :--- | :--- | :--- |
| `__enter__()` | 进入 with 块 | 返回值赋给 `as` 后的变量 |
| `__exit__()` | 离开 with 块（含异常） | 清理资源 |

`__exit__` 返回 `True` 可吞掉异常，返回 `False`/`None` 则异常继续抛出。

### 常见场景
```python
# 文件
with open("a.txt") as f: ...

# 线程锁（自动加锁/解锁）
with lock: ...

# 同时打开多个文件
with open("a.txt") as f1, open("b.txt") as f2: ...

# 异步上下文管理器
async with session.get(url) as resp: ...
```

### 自定义上下文管理器

 **方式一：类实现** 
```python
class MyResource:
    def __enter__(self):
        print("获取资源")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("释放资源")
        return False

with MyResource() as r:
    print("使用资源")
```

 **方式二：装饰器（更简洁）** 
```python
from contextlib import contextmanager

@contextmanager
def my_resource():
    print("获取资源")
    try:
        yield "资源对象"   # yield 的值即 as 接到的值
    finally:
        print("释放资源")   # 相当于 __exit__

with my_resource() as r:
    print("使用资源")
```
> `yield` 必须放在 try 里，否则块内抛异常时释放逻辑不会执行。
